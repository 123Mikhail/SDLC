## 1. Введение {#1-introduction}

Настоящий документ представляет собой спецификацию требований к программному обеспечению (SRS) для десктопной кроссплатформенной системы персонального финансового учета FinanceTracker (версия 0.2). Продукт предназначен для автоматизированного учета доходов и расходов, контроля остатков на счетах и аналитической агрегации данных без передачи персональных сведений во внешние облачные сервисы. Документ определяет функциональные и качественные границы системы для использования при проектировании, реализации и верификации в рамках учебного курса.

### 1.1 Назначение документа {#11-document-purpose}

Настоящий SRS носит нормативно-закрепительный характер и регламентирует исчерпывающий перечень функциональных и нефункциональных требований к системе FinanceTracker. Документ служит технической договоренностью между разработчиком и проверяющей стороной (Заказчиком / преподавателем) на этапах сбора требований, архитектурного проектирования (SDD) и последующей программной реализации.

### 1.2 Область применения продукта {#12-product-scope}

Приложение FinanceTracker представляет собой автономную десктопную систему, ориентированную на локальный учет персональных или семейных денежных потоков с акцентом на приватность и высокую скорость обработки локальных данных.

**В область применения продукта входит:**
- Учет операций поступления и расхода денежных средств с детализацией по дате, сумме, категории и назначению платежа.
- Оперативный перерасчет агрегированного баланса счетов в режиме реального времени.
- Месячная и интервальная группировка транзакций с расчетом процентного соотношения статей затрат.
- Фильтрация финансового реестра по ключевым словам, категориям и календарным периодам.
- Экспорт сводных данных и истории транзакций в структурированный текстовый формат CSV.

**В область применения НЕ входит:**
- Прямая интеграция с банковскими API и автоматическое списание реальных денежных средств со счетов.
- Синхронизация транзакций через сторонние публичные облачные хранилища.
- Инвестиционный трейдинг и расчет котировок ценных бумаг на биржах.

## 2. Обзор продукта {#2-product-overview}

### 2.1 Перспектива продукта {#21-product-perspective}

FinanceTracker разрабатывается как легковесный автономный десктопный инструмент, не зависящий от сетевой инфраструктуры и внешних серверов. Приложение запускается непосредственно на рабочей станции пользователя под управлением виртуальной машины Java (JVM), сохраняя финансовую историю в локальную реляционную базу данных SQLite. Продукт решает задачу конфиденциального и прозрачного бюджетирования без рисков утечки финансовых метаданных.

### 2.2 Функции продукта {#22-product-functions}

На основе спроектированного интерфейса приложение предоставляет следующие ключевые возможности:
- **Отображение финансовой сводки:** Вывод общего баланса, а также суммарного месячного дохода и расхода.
- **Интерактивный реестр транзакций:** Табличный просмотр всех учтенных операций (дата, категория, описание, статус операции, сумма в валюте).
- **Регистрация финансовых операций:** Диалоговая форма добавления доходных и расходных транзакций с валидацией числовых значений.
- **Динамическая фильтрация:** Поиск операций по строке описания, а также выборка по конкретным категориям трат.
- **Экспорт данных:** Формирование выгрузки полного журнала операций в формат CSV для последующей обработки в табличных процессорах.

### 2.3 Ограничения продукта {#23-product-constraints}

- **Кроссплатформенность:** Программное обеспечение должно гарантированно выполняться в операционных системах семейств Windows 10/11, Linux (Ubuntu, Fedora) и macOS (12+).
- **Технологический стек:** Разработка ведется на языке Java (версия Java SE 17 LTS или выше) с использованием UI-библиотек JavaFX / Swing.
- **Локальность данных:** Вся финансовая история хранится исключительно на локальном дисковом накопителе пользователя в формате SQLite / H2.
- **Поддержка валют:** Система должна обеспечивать расчет и хранение денежных значений в базовых расчетных единицах (BYN, USD, EUR) с точностью до сотых долей (2 знака после запятой).
- **Ограничения по объему кэша:** Локальная база данных оптимизирована под хранение до 100 000 транзакций без деградации времени отклика интерфейса.

### 2.4 Характеристики пользователей {#24-user-characteristics}

Основной целевой аудиторией FinanceTracker являются:
- **Частные пользователи и студенты:** Лица, ведущие регулярный контроль личных карманных расходов, стипендий, заработных плат и коммунальных платежей.
- **Пользователи с повышенными требованиями к приватности:** Граждане, принципиально отказывающиеся от облачных банковских ассистентов и веб-трекеров из соображений безопасности персональных данных.

Интерфейс не требует специализированной финансовой квалификации и ориентирован на базовые навыки работы с офисными десктопными приложениями.

### 2.5 Допущения и зависимости {#25-assumptions-and-dependencies}

- **Допущение о локальном времени:** Корректность хронологической сортировки опирается на системные часы операционной системы рабочей станции.
- **Зависимость от прав файловой системы:** Для инициализации и обновления локального файла БД процессу приложения требуется право на запись в рабочий каталог или папку профиля пользователя (`user.home`).

### 2.6 Распределение требований {#26-apportioning-of-requirements}

- **Фаза 1 (5 семестр, 2026 г.):** Анализ предметной области, согласование бизнес-требований (SRS), визуальное прототипирование в Excalidraw, моделирование интерфейса на SysMLv2.
- **Фаза 2 (6 семестр, 2027 г.):** Программная реализация на Java, связывание GUI с СУБД SQLite, функциональное и модульное тестирование.
- **Будущие итерации:** Модуль автоматического построения графиков и диаграмм динамики накоплений.

## 3. Требования {#3-requirements}

### 3.1 Внешние интерфейсы {#31-external-interfaces}

#### 3.1.1 Пользовательские интерфейсы {#311-user-interfaces}

Пользовательский интерфейс представляет собой однооконное десктопное приложение. Графический мокап представлен в Приложении А.

**Структурная спецификация интерфейса на языке SysMLv2:**

```sysml
package FinanceTrackerUI {
    public part def MainWindow {
        part summaryBar : AccountSummaryPanel;
        part transactionTable : TransactionDataGrid;
        part entryPanel : TransactionEntryPanel;
    }

    part def AccountSummaryPanel {
        attribute totalBalanceText : String;
        attribute monthlyIncomeText : String;
        attribute monthlyExpenseText : String;
        part searchFilterInput : TextField;
        part exportCsvButton : Button [1] { attribute label = "Экспорт CSV"; }
    }

    part def TransactionDataGrid {
        part transactionRows : TransactionRow [*];
    }

    part def TransactionRow {
        attribute date : String;
        attribute category : String;
        attribute description : String;
        attribute operationType : String; // "Доход" | "Расход"
        attribute amount : String;
    }

    part def TransactionEntryPanel {
        part addTransactionButton : Button [1] { attribute label = "+ Добавить операцию (Расход / Доход)"; }
    }
}
